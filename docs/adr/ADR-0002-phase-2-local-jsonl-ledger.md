# ADR-0002：Phase 2 使用本地 JSONL 追加式账本

## 状态

已接受

## 背景

Phase 2 需要保存来自工作契约证据和 agent 会话记录的事件，并从中生成候选学习项。当前项目仍处于个人本地 MVP 阶段，不需要数据库、服务端或团队权限系统。

账本必须可读、可测试、可追踪，并且不能把事件直接提升为 memory、rule 或 skill。

## 决策

Phase 2 使用本地 JSONL 文件作为追加式（append-only）账本：

```text
.argus/
  ledger/
    events.jsonl
    candidate_learnings.jsonl
    reports/
```

事件和候选学习项都以追加方式写入。状态变化通过新记录、替代记录或后续状态事件表达，避免原地覆盖历史。

## 替代方案评估

- SQLite：查询能力更强，但 Phase 2 早期会增加迁移和调试复杂度。
- Markdown 账本：人类可读性好，但结构化测试和引用证据较弱。
- 直接写 memory / rules：短期看起来有用，但违反"事件不是记忆"的核心原则。
- 云端数据库：团队版可能需要，但当前过重且削弱本地优先信任。

## 后果

正面影响：

- 易于调试和人工审查。
- 易于用固定样本（fixture）做稳定测试。
- 保持本地优先和低风险。
- 后续可以迁移到 SQLite 或服务端存储。

代价和风险：

- 查询能力有限。
- 需要自己处理重复导入和证据引用（evidence refs）。
- JSONL 破损时需要容错策略。

## 复核触发条件

- 账本数据量大到 JSONL 读写明显变慢。
- Phase 3/4 需要复杂查询或 join。
- 团队版需要并发写入、权限、审计和远程同步。
