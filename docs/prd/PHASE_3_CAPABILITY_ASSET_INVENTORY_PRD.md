# Phase 3: 个人本地能力资产清单 PRD

> 上下文加载：新会话默认先读 `docs/context/CURRENT_HANDOFF.md`，再按需读取本 PRD。本文件只回答产品问题，不承担实现任务管理。

## 1. 背景

Phase 2 已经建立事件账本和候选学习账本，但学习项仍然只是候选判断。Phase 3 要证明 Argus 管理的是能力资产，而不是只记录 memory 或学习摘要。

能力资产包括 skills、plugins、MCP config、rules、scripts、memory 等本地 AI 工作能力。用户需要先看见这些资产，后续才能治理、组合、安装、修改、删除、合并或回滚。

## 2. 用户与任务

目标用户：

- 中重度 AI 产出者。
- 使用 Codex、Claude Code 或类似 agent 工具的开发者。
- 希望了解本机 AI 能力资产全貌的个人用户。

用户任务：

- 扫描本机能力资产。
- 查看资产类型、来源、路径、权限、风险和状态。
- 发现重复或疑似冲突能力。
- 判断候选学习项是否已有现成能力可以复用。

## 3. 问题

当前问题：

- 用户不知道本机到底装了哪些 skill、plugin、MCP、rule、script 和 memory。
- 候选学习项不知道应该复用已有能力，还是创建新能力。
- 重复能力和冲突能力很难被发现。
- 若直接进入自动修改，会缺少可信资产视图。

## 4. 目标

本阶段目标：

- 定义 `CapabilityAsset` 模式。
- 建立只读本地扫描器。
- 生成能力资产清单。
- 生成资产扫描报告。
- 将候选学习项轻量关联到现有资产。
- 标记重复或疑似重叠能力。

## 5. 非目标

本阶段不做：

- 不安装外部能力。
- 不修改、删除、禁用、归档、合并任何能力资产。
- 不写入全局 agent 配置。
- 不做团队权限、共享策略或审计后台。
- 不承诺完整供应链安全扫描。

## 6. 核心用户流程

### 流程 1：扫描本地能力资产

1. 用户运行 `argus assets scan --profile local-codex`，或运行 `argus assets scan` 并指定本地路径。
2. Argus 只读扫描 skill、plugin、MCP config、rule、script、memory。
3. Argus 写入 `.argus/assets/inventory.json`。
4. 用户得到资产数量、警告和报告路径。

### 流程 2：查看资产清单

1. 用户运行 `argus assets list`。
2. Argus 输出统一 `CapabilityAsset` JSON。
3. 用户可以看到名称、类型、来源、安装路径、权限、风险评分、状态。

### 流程 3：生成资产报告

1. 用户运行 `argus assets report`。
2. Argus 生成 Markdown 报告。
3. 报告显示资产类型统计、风险分布、潜在重复项、潜在冲突项和高关注风险资产。

### 流程 4：关联候选学习项

1. 用户已有候选学习账本。
2. 用户运行 `argus assets link-learnings`。
3. Argus 输出候选学习项到资产的关联报告。
4. 用户可以判断某个学习项是否已有本地能力可复用。

## 7. 验收标准

- 能展示当前本机 agent 能力资产全貌。
- 至少支持 skills、plugins、MCP config、rules、scripts、memory。
- 扫描过程只读，不修改源资产。
- 能发现重复或疑似重叠能力。
- 能判断候选学习项是否可能已有本地能力可复用。
- 固定测试集能稳定生成清单、报告和关联报告。

## 8. 风险与开放问题

风险：

- 不同 agent 的 skill/plugin/MCP 格式差异较大，第一版必须保持适配层可扩展。
- 风险评分早期只能是启发式，不能包装成安全结论。
- 路径扫描如果范围过大，可能产生噪声。

开放问题：

- 默认扫描配置应包含哪些本机目录。
- MCP config 是否应优先支持 JSON、TOML，还是按 agent 适配器分离。
- 候选学习项到资产的关联是否应引入更强文本匹配或向量嵌入。
