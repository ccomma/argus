# Phase 5: 个人治理报告 PRD

> 上下文加载：新会话默认先读 `docs/context/CURRENT_HANDOFF.md`，再按需读取本 PRD。本文件只回答产品问题，不承担实现任务管理。

## 1. 背景

Phase 4 已经能把能力资产组合成包，并绑定到工作契约和角色包。Phase 5 要进入个人治理：让用户看到哪些契约、角色、学习项、资产、包需要处理，而不是让系统直接修改全局行为。

## 2. 用户与任务

目标用户：

- 中重度 AI 产出者。
- 希望定期审视本机 agent 能力状态的个人用户。
- 需要在自动化前看到风险、缺口和待处理动作的开发者。

用户任务：

- 生成治理报告。
- 查看低风险维护日志。
- 查看待处理动作列表。
- 判断工作契约是否清晰。
- 判断角色和能力资产是否存在风险、重复或过期。

## 3. 问题

当前问题：

- 工作契约、角色包、候选学习项、资产和包分散在不同目录。
- 用户无法一次性回答"哪些需要处理、风险在哪里、哪些可以安全自动化"。
- 低风险动作缺少审计记录。
- 治理建议如果直接修改 skill/plugin/MCP，会过早进入高风险行为变更。

## 4. 目标

- 生成个人版治理报告。
- 输出低风险维护日志。
- 输出待处理动作列表。
- 覆盖去重、过期、风险、工作契约改进、角色改进五类治理发现。
- 输出提问策略和交付物契约两类改进建议。
- 保持只读，不修改源能力资产或角色档案。

## 5. 非目标

- 不自动修改 skill、plugin、MCP、rule、script、memory。
- 不自动修改角色档案或角色包。
- 不执行归档、禁用、合并、安装、删除。
- 不做团队治理后台。
- 不做调度器。

## 6. 核心用户流程

1. 用户运行 `argus governance report`。
2. Argus 读取工作契约、候选学习项、资产清单、能力包、角色包。
3. Argus 生成 Markdown 和 JSON 治理报告。
4. Argus 写入低风险维护日志。
5. Argus 写入待处理动作。
6. 用户决定哪些建议进入后续治理或受控修改流程。

## 7. 验收标准

- 报告回答：工作契约是否清晰、角色做了什么、学到了什么、有哪些能力、哪些可能有风险、哪些建议处理。
- 完成五类治理输出：去重、过期、风险、工作契约改进、角色改进。
- 输出提问策略改进。
- 输出交付物契约改进。
- 低风险动作有记录，可审计。
- 没有未经确认的全局规则、skill、plugin、MCP、角色档案修改。

## 8. 风险与开放问题

风险：

- 当前报告是启发式治理建议，不是自动修复。
- 真实本机扫描可能只有部分发现类别；测试集覆盖完整验收类别。
- 候选学习项的重复检测仍然保守。

开放问题：

- Phase 6 能力决议决策枚举的最终证据格式。
- 治理动作是否需要独立状态机。
- 周期性报告是否使用定时自动化还是外部调度。
