# Phase 1: 追问模式工作契约 MVP PRD

> 上下文加载：新会话默认先读 `docs/context/CURRENT_HANDOFF.md` 和阶段 `HANDOFF.md`。本文件只回答 Phase 1 的产品需求和验收口径，不承担执行状态管理。

## 1. 背景

Phase 1 承接 Phase 0 的设计和文档骨架，目标是验证 Argus 最直接的用户价值：用户只表达模糊意图，Argus 主动追问并生成可执行、可验收、可复盘的工作契约。

这一阶段不优先证明"Argus 能管理多少能力资产"，而是先证明"Argus 能把用户不知道如何表达的复杂工作，转化成专业、可执行的工作协议"。

## 2. 用户与任务

目标用户：

- 中度或重度使用 AI 完成实际产出的人。
- 需要做产品、研究、写作、开发、运营、咨询、分析等复杂任务的 AI 重度用户。
- 当前首要用户是项目维护者本人，用真实 Argus 开发流程验证产品价值。

用户任务：

- 用一句模糊意图启动复杂工作。
- 让 Argus 判断还缺哪些关键信息。
- 通过少量追问补齐目标、背景、输入、输出、约束、风险和验收标准。
- 得到一份可执行的工作契约。
- 从工作契约派生 PRD、阶段计划、研究计划或技术前置问题。
- 检查交付物是否满足工作契约。

## 3. 问题

当前问题：

- 用户往往知道自己想做什么，但不知道专业流程应该先问什么、产出什么、何时足够清晰。
- 普通聊天会生成很多文本，但缺少目标、边界、确认点和验收标准。
- 需求变化容易散落在对话中，后续执行和复盘缺少稳定依据。
- 如果第一步就做能力治理，用户价值不够显性，难以证明 Argus 与普通记忆/技能工具的差异。

## 4. 目标

本阶段目标：

- 支持从模糊意图生成工作契约。
- 支持快速、标准、严格三种追问深度。
- 支持提问策略判断信息缺口。
- 支持完整度评分判断是否可以开始执行。
- 支持交付物契约定义交付物结构和验收要求。
- 支持交付物评估器对照工作契约输出通过、部分通过或缺失项。
- 为 Phase 2 的事件账本、执行证据和反向学习保留数据边界。

## 5. 非目标

本阶段不做：

- 不自动安装外部 skill、MCP、plugin、package 或可执行工具。
- 不自动修改 skill、rule、memory、AGENTS.md、MCP config 或全局配置。
- 不实现完整能力清单。
- 不实现团队权限、共享策略或组织审计。
- 不实现完整仪表盘。
- 不把一次工作契约对话直接提升为长期规则。
- 不追求大量角色模板，最多用 1-2 个角色作为能力组合示例。

## 6. 核心用户流程

### 流程 1：模糊意图到工作契约

1. 用户输入模糊意图，例如"我想做一个帮助 AI 用户更高效工作的工具"。
2. Argus 选择默认提问策略和追问深度。
3. Argus 输出第一轮关键追问。
4. 用户回答或选择跳过部分问题。
5. Argus 更新完整度评分。
6. Argus 判断继续追问或生成工作契约。
7. 用户确认工作契约。

### 流程 2：工作契约到结构化交付物

1. 用户选择交付物类型，例如 PRD、阶段计划、研究计划。
2. Argus 根据交付物契约生成结构化交付物。
3. Argus 用交付物评估器检查交付物是否覆盖工作契约。
4. 用户看到通过、部分通过或缺失项结果。

### 流程 3：工作契约变更

1. 用户补充新约束或改变目标。
2. Argus 生成新的工作契约版本。
3. Argus 记录变更历史。
4. Argus 说明变更对交付物和后续执行的影响。

## 7. 验收标准

验收标准：

- 给定固定模糊意图测试集，Argus 能稳定输出追问问题。
- 追问结果能生成包含目标、背景、输入、输出、约束、风险、确认点、验收标准和完成定义的工作契约。
- 完整度评分能解释当前信息为什么足够或不足。
- 至少一个真实项目场景能从模糊意图走到可执行阶段计划。
- 交付物评估器能指出交付物缺失项，而不是只给泛泛评价。
- 所有输出默认本地保存或打印，不产生高风险持久行为变更。

## 8. 风险与开放问题

风险：

- 追问过多会变成负担，过少又会导致契约质量不足。
- 完整度评分早期可能偏启发式，不能假装成精确客观指标。
- 交付物评估器容易变成普通总结，需要严格对照契约字段检查。
- 如果数据模型太复杂，会拖慢 MVP。

开放问题：

- 第一版 CLI 是否只支持单轮命令，还是支持交互式会话？
- 工作契约第一版应使用 Markdown、JSON、YAML，还是混合格式？
- Phase 1 是否需要最小角色档案，还是先只保留角色/工作模式字段？
- 交付物评估器第一版是否只做规则检查，还是允许 LLM 判断？
