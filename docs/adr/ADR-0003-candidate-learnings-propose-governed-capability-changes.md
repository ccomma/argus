# ADR-0003：候选学习项应以治理提案方式驱动能力变更

## 状态

已接受

## 背景

候选学习项记录了观察到的纠正、失败和成功模式，但它们不得直接修改能力资产或能力包。当一项学习需要变为持久行为时，它应提出一项能力变更提案，由治理策略审查后执行。这样即使直接修改在 MVP 阶段更简单，也能保留可审计性、隔离性、确认机制和回滚路径。

## 决策

候选学习项记录学习内容，但不直接写入能力资产。任何持久行为变更都必须经过治理策略审查。候选学习项的典型生命周期为：

1. 从事件账本中生成候选学习项。
2. 候选学习项提出能力变更提案。
3. 治理策略根据风险等级决定自动执行、建议确认或要求人工审批。
4. 执行后的变更记录审计日志和回滚信息。

## 替代方案评估

- 直接修改能力资产：MVP 实现最简单，但失去了可审计性、可追溯性和回滚能力，且"学习"与"能力"边界模糊。
- 将学习项写入 memory：看似合理，但 memory 是能力的运行时输入，不是学习记录的存储层，混淆了两种不同的职责。

## 后果

正面影响：

- 学习与能力之间的边界清晰，可审计、可回滚。
- 候选学习项可以累积、去重、关联，不会立即污染能力资产。
- 治理策略层有明确的输入和决策点。

代价和风险：

- 比直接修改多了中间层，增加实现复杂度。
- 需要额外维护候选学习项的生命周期状态。

## 复核触发条件

- 候选学习项大量堆积，治理策略无法有效处理。
- 用户需要更直接的学习到能力转化路径。
- 自动学习场景需要低延迟修改时。
