# Phase 6: 能力解析与受控安装建议 PRD

> Context loading: 新会话默认先读 `docs/context/CURRENT_HANDOFF.md`，再按需读取本 PRD。本文件只回答产品问题，不承担实现任务管理。

## 1. Background

Phase 5 已经能生成个人版治理报告，标记去重、过期、风险、工作契约改进、角色改进五类治理发现。但这些发现仍是启发式建议——用户知道了"有问题"，却不知道"本地有没有可复用的东西"、"要不要从外部装"、"自己建还是改现有的"。

Phase 6 要回答的核心问题是：当一个能力缺口被识别出来（无论是来自反向学习、能力包检查、治理报告还是手动输入），Argus 应先查本地，再给外部建议，最终给出明确的可操作决策——复用、配置、安装建议、本地创建、合并或忽略。高风险的外部安装默认不自动执行。

## 2. Users and Jobs

目标用户：

- 中重度 AI 产出者，需要判断能力缺口是缺知识、缺流程还是缺工具。
- 已有一定本地能力资产基础（skill、MCP、plugin 等），希望优先复用而非盲目安装的开发者。
- 从治理报告中发现能力缺口后，需要系统帮忙给出"下面怎么做"的决策建议的用户。

用户任务：

- 输入一个能力缺口描述，获得该缺口是"已有、可配、可仿建、只能外装"的结论。
- 从候选学习项中提取反向学习目标，自动生成能力解析。
- 从能力包咨询的缺失能力列表中批量解析。
- 从治理报告的去重/风险/角色发现中构建能力缺口并解析。
- 查看每条建议的证据和置信度，判断是否采纳。

## 3. Problem

当前问题：

- 治理报告能发现重复、过期、风险、角色缺失等问题，但不能给出"到哪找、能不能复用、要不要外部装"的答案。
- 候选学习项中有反向学习目标（如指向 capability_pack、deliverable_contract），但这些信号未与本地资产关联。
- 能力包咨询返回的缺失能力列表仅提供名称，未做本地匹配。
- 用户缺少一个统一的引擎来判断"缺的东西在本地有没有、能不能改，还是只能去找外部"。

## 4. Goals

- 提供四级能力匹配引擎：精确复用（REUSE）-> 部分配置（CONFIGURE）-> 相似仿建（CREATE_LOCAL）-> 外部安装建议（INSTALL_SUGGESTED）。
- 支持四种缺口输入来源：手动传入缺口、候选学习项反向目标、能力包缺失建议、治理发现。
- 每条决策附带证据列表、匹配置信度和风险等级。
- 高风险外部安装默认仅建议不执行。
- 输出 Markdown 和 JSON 双格式解析报告，汇总按决策类型和风险等级的统计。

## 5. Non-goals

- 不执行自动安装外部能力。
- 不自动修改本地能力资产。
- 不做外部能力市场的搜索或爬虫。
- 不替代 Phase 5 的治理报告，而是在其基础上增加"下一步动作"的决策建议。

## 6. Core User Flows

1. 用户运行 `argus resolution resolve --gap "需要 pdf 生成能力"`，或在 MCP 中调用 `run_resolution`。
2. Argus 提取缺口关键词，与本地资产清单执行四级匹配：
   - 精确匹配（关键词覆盖资产 tokens >= 50%）：决策为 REUSE，风险低，置信度 0.9。
   - 部分匹配（关键词重叠分 >= 0.15）：决策为 CONFIGURE，风险低，置信度取最高匹配分。
   - 弱相似（重叠分在 0 到 0.15 之间）：决策为 CREATE_LOCAL，风险中等，置信度 0.55。
   - 无匹配：决策为 INSTALL_SUGGESTED，风险高，置信度 0.3。
3. Argus 按 gap_id 去重后返回 CapabilityResolution 列表。
4. Argus 生成双格式报告（Markdown + JSON），展示每条决策的类型、风险、置信度和证据。

多源输入变体：

- `resolve_from_learnings`：从候选学习项中提取 reverse_learning_target 为 capability_pack 或 deliverable_contract 的记录。
- `resolve_from_advice`：从能力包咨询返回的缺失能力名称列表构建缺口。
- `resolve_from_findings`：从治理发现中提取 dedupe、risk、role 三类发现构建缺口。

## 7. Success Criteria

- 同一缺口能先查本地资产，按四级匹配策略给出决策建议。
- 六级决策枚举（reuse / configure / install_suggested / create_local / merge / ignore）均已建模。
- 每条建议有证据列表和置信度。
- 高风险外部安装不会自动触发实际安装动作。
- 能区分"本地已有可配置"和"只能建议外部查找"两类情况。
- 解析报告包含按决策类型和风险等级的汇总统计。

## 8. Risks and Open Questions

风险：

- 当前关键词匹配算法仅基于名称、类型、来源和权限的简单重叠分，可能对语义相近但表述不同的能力产生误判。
- 缺少对能力资产实际功能是否完整覆盖缺口的验证——复用建议的本质是"名字和关键词像"，不代表功能真的满足。
- merge 和 ignore 两种决策在四级匹配算法中未自动生成，仅在枚举中预留。

开放问题：

- 是否需要引入能力资产的"功能描述"或"使用场景"字段以提高匹配精度？
- 外部能力选项是否应关联到特定的可信 registry（如 Skillsmith）？
- Phase 7 的受控修改如何消费这些决策建议（例如 create_local 决策触发实际创建流程）？
