# Phase 4: 能力包与角色组合 PRD

> 上下文加载：新会话默认先读 `docs/context/CURRENT_HANDOFF.md`，再按需读取本 PRD。本文件只回答产品问题，不承担实现任务管理。

## 1. 背景

Phase 3 已经能只读扫描本地能力资产。Phase 4 要把这些零散资产组合成可审计、可检查、可绑定到工作的能力包，让 Argus 从"看见能力"进入"组合能力"。

## 2. 用户与任务

目标用户：

- 中重度 AI 产出者。
- 需要按工作契约、角色或工作模式复用能力组合的开发者。
- 希望在使用能力前看到版本、风险、权限和漂移情况的个人用户。

用户任务：

- 为一个工作契约绑定具体能力包。
- 为产品经理/产品策略师等角色建立默认能力组合。
- 检查能力包是否完整、是否发生漂移。
- 发现缺失能力和重复能力。

## 3. 问题

当前问题：

- 扫描出来的资产仍然是零散清单，不能表达"这项工作需要哪些能力"。
- 同一工作契约重跑时，如果能力变化，缺少包版本和内容哈希证据。
- 角色没有默认能力组合，未来 agent 不知道该复用哪些能力。
- 缺口、重复能力和漂移只能人工判断。

## 4. 目标

- 定义带版本的能力包清单文件。
- 支持必选/可选资产条目和选择理由。
- 记录风险策略版本、风险快照、权限快照和内容哈希。
- 支持工作契约绑定具体的 `pack_id + version + content_hash`。
- 支持角色能力包引用能力包。
- 支持缺失能力和重复资产报告。
- 支持执行前检查，且检查不改写清单文件。

## 5. 非目标

- 不安装外部能力。
- 不修改、删除、禁用、归档、合并源能力资产。
- 不做嵌套包。
- 不做远程包注册中心。
- 不做用户可配置风险策略。
- 不做完整治理审批流程。

## 6. 核心用户流程

### 流程 1：创建能力包

1. 用户先运行 `assets scan`。
2. 用户用资产 ID 运行 `packs create`。
3. Argus 写入 `.argus/capability-packs/<pack_id>/<version>.json`。
4. 输出清单文件、版本、内容哈希。

### 流程 2：检查能力包

1. 用户运行 `packs check <pack_id>`。
2. Argus 对比清单文件快照和当前资产清单。
3. 报告完整、缺失必选条目、漂移条目和当前综合风险。
4. 检查不改写清单文件。

### 流程 3：绑定工作契约

1. 用户创建工作契约。
2. 用户运行 `contract bind-pack <contract_id> <pack_id>`。
3. Argus 将具体包版本和内容哈希写入契约证据。
4. 契约显示 `capability_pack_ref`。

### 流程 4：创建角色能力包

1. 用户运行 `roles create-pack`。
2. 角色包引用已有能力包，不内联资产条目。
3. 用户运行 `roles check-pack` 复用包检查结果。

### 流程 5：能力缺口和重复提示

1. 用户运行 `packs advise --required-capability ...`。
2. Argus 在当前资产清单中查找缺失能力。
3. Argus 报告潜在重复资产组。

## 7. 验收标准

- 至少一个工作契约能展示完整能力包绑定。
- 至少一个产品经理角色能展示完整角色能力包。
- 包条目能说明能力被选择的理由。
- 能发现缺失能力和重复能力资产。
- 绑定记录契约版本、包版本和内容哈希。
- 能力包默认只读，不自动安装外部能力。

## 8. 风险与开放问题

风险：

- 风险策略仍是确定性启发式，不应被包装成安全结论。
- 角色包目前只引用包，尚未表达完整角色工作流。
- 包建议是轻量文本匹配，可能漏报或误报。

开放问题：

- Phase 5 治理报告的读者、格式和处理动作。
- 角色档案是否需要单独模式。
- 执行证据何时从契约本地证据升级为独立运行记录。
