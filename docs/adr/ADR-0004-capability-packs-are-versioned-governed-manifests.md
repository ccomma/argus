# ADR-0004：能力包是有版本、受治理的清单文件

## 状态

已接受

## 背景

能力包是选定能力资产的持久化、带版本的清单文件，而不是临时的解析器输出。任何持久内容变更都会创建新版本的能力包。Phase 4 从简单的整数版本号加内容哈希开始，不采用 SemVer。能力解析器可以提出能力变更提案来创建或更新能力包，但治理策略必须在能力包形成或更新之前批准该变更。

## 决策

能力包的核心属性：

- 能力包是持久化的清单文件（manifest），不是运行时解析结果。
- 每次内容变更创建新版本。版本标识采用 `version（整数） + content_hash（SHA-1）`。
- 能力包的创建和更新必须经过治理策略审批，不能由解析器或学习模块直接写入。
- 能力包版本之间保留变更记录，支持 diff 和回滚。

## 替代方案评估

- SemVer 版本号：对能力包的变更语义（major/minor/patch）在 Phase 4 阶段难以准确判断，简单整数版本号足够并降低复杂度。
- 不加治理直接创建能力包：实现了灵活性，但失去了能力组合的可信度和可追溯性。
- 能力包作为解析器动态输出：轻量但不可追溯、不可审计、不可回滚，违背项目核心原则。

## 后果

正面影响：

- 能力包可审计、可 diff、可回滚。
- 每个版本有明确的创建原因和审批记录。
- 治理策略可以通过能力包的版本历史判断能力组合的质量变化。

代价和风险：

- 版本管理增加实现复杂度和存储开销。
- 整数版本号在长期可能需要迁移到更丰富的版本标识方案。
- 审批流程可能在某些场景下显得过重。

## 复核触发条件

- 整数版本号无法满足能力包的依赖表达需求。
- 审批流程成为频繁使用的瓶颈。
- 需要支持能力包的并发编辑或分支。
